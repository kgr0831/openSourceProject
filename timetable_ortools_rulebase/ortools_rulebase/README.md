# 맞춤형 시간표 추천 시스템 — OR-Tools 필수 룰베이스

버전 1.0.0 · 작성일 2026-11-01 · 팀 전달용 구현 명세

## 1. 문서의 목적과 완료 기준

강의 데이터와 사용자 조건으로 시간표를 만들고, 추천 이유·비교·수강신청 실패 대체안·최소 조건 완화를 제공한다. **운영 후보 생성과 최적화 엔진은 Google OR-Tools CP-SAT을 반드시 사용한다.**

이 파일은 구현 규칙과 완료 기준이다. 현재 사용자 PC의 Node.js 구현을 OR-Tools로 전환하거나 실행 검증했다는 보고서가 아니다. 앞서 보고된 DemoCandidateProvider와 Node.js 테스트 통과는 기존 기능의 근거이며 OR-Tools 사용 완료 증거를 대신하지 않는다.

완료로 인정하려면 다음을 모두 만족해야 한다.

1. 정상 추천·분반 실패 대체·최소 조건 완화의 실제 실행 경로가 CP-SAT 모델을 생성하고 solve를 호출한다.
2. 선택 분반과 최적화 결과가 CP-SAT의 실제 해에서 나온다.
3. 원래 조건 및 완화한 조건을 각각 재검증하고, 사용한 엔진·버전·상태·목표값·증명 범위를 기록한다.
4. 실제 CP-SAT 제공자를 연결해 기존 회귀와 완화 검증을 수행한다.
5. 라이브러리/worker 장애 시 명시적 엔진 오류를 반환한다. DemoCandidateProvider로 자동 대체하지 않는다.

작은 전수 탐색 코드는 테스트의 독립 기준 계산기로 유지할 수 있다. CP-SAT을 import만 하거나, 전체 후보를 기존 코드로 만든 뒤 형식적으로 CP-SAT에 통과시키는 방식은 이 조건을 만족하지 않는다.

## 2. 권장 연결 구조

기존 Node.js 결과 처리 코드를 유지하고 **Python OR-Tools worker + Node.js OrToolsCandidateProvider 어댑터**를 연결한다. 팀에 이미 공식 지원 언어 기반 OR-Tools 엔진이 있다면 같은 의미의 계약으로 연결할 수 있다.

| 구성 | 책임 |
|---|---|
| 데이터 어댑터 | 공통 카탈로그, 과목/분반 ID, 학기, 모든 수업 블록, 검증된 학점 |
| Python CP-SAT worker | 변수·제약·목표 구성, 원래 조건 탐색, Top-K, 최소 변경·최소 완화 최적화 |
| Node.js 제공자 어댑터 | 기존 호출을 worker 입력으로 변환, 실행 예산·오류·결과 전달 |
| 기존 Node.js 도메인 기능 | 해 재검증, 지표 확인, 근거 기반 설명, 비교 JSON, CLI |
| 프론트/백엔드 | 요청 전달, 저장, 시간표·변경 내용 표시 |

MVP는 자식 프로세스의 표준입력/표준출력으로 JSON을 전달해도 된다. 새 웹 프레임워크는 필수가 아니다. 입력값을 셸 명령에 이어 붙이지 말고 프로세스 인자와 stdin을 사용한다. 결과 JSON과 진단 로그를 분리하고, 한글 과목명은 UTF-8로 보존한다. 기존 함수가 동기식이면 worker 대기로 인한 호출 계약 변경을 문서화하고 호출부 테스트를 수정한다.

실제 실행 결과에는 `engine=ortools-cp-sat`와 설치된 실제 버전을 넣는다. 버전을 추측하거나 최신이라는 문자열로 대체하지 않는다. 검증한 버전을 의존성 파일에 고정한다.

## 3. 공통 입력 규칙

- 학기와 데이터 버전을 요청마다 명시한다. 2026년 2학기는 시연 값이며 프로그램 상수가 아니다.
- `course_id`는 과목, `section_id`는 분반이다. 이름만으로 동일 과목을 판단하거나 모든 ID의 끝 두 글자를 일괄 삭제하지 않는다.
- 한 분반의 모든 요일·시간 블록을 함께 선택한다. 학점은 분반당 한 번만 합산한다.
- 시간은 자정부터의 정수 분이며 `[시작, 종료)` 구간이다. 15분 단위로 임의 반올림하지 않는다.
- CP-SAT에 넣는 학점은 정확한 정수 배율을 적용한다. 예를 들어 1.5학점이 있으면 2배 하여 3으로 모델링하고 입출력에서 원래 단위를 복원한다. 이진 부동소수점 오차를 반올림으로 숨기지 않는다.
- 시간·학점·ID가 미상인 강좌는 진단에 기록한다. 미상 시간을 공강으로 처리하지 않는다.
- 학년과 수강 대상 필터는 제공된 데이터 의미에 맞춘다. '3학년'이라는 이유로 전교 모든 과목의 수강 자격을 판정했다고 주장하지 않는다.
- 기존 시연은 3학년 명시 소프트웨어 계열 28개 분반을 사용했다. 원래 점심 조건으로 19개만 남긴 목록을 완화 엔진의 전체 입력으로 재사용하면 안 된다.

완화 가능 조건 때문에 강좌를 원본 카탈로그에서 영구 제거하지 않는다. 원래 조건 모델과 완화 모델이 같은 기준 카탈로그를 공유하게 한다. 원래 조건 전용 전처리를 했다면 완화 모델에는 원본을 복원한다.

## 4. 규칙 분류

세 종류를 구분한다.

1. **보호 조건**: 어떤 추천·완화·대체 모드에서도 유지.
2. **사용자 조건**: 정상 추천에서는 반드시 만족. 완화 기능에서 명시적으로 허용한 값으로만 조정.
3. **선호 목표**: 조건을 충족하는 시간표 중 어떤 안을 먼저 보여줄지 결정.

| ID | 종류 | 규칙 | IF → THEN |
|---|---|---|---|
| H001 | 보호 | 시간 중복 금지 | 같은 요일 두 블록이 겹치면 해당 두 분반 동시 선택 금지 |
| H002 | 보호 | 같은 과목 중복 금지 | course_id가 같으면 분반 최대 하나 선택 |
| H003 | 사용자 | 학점 범위 | 선택 학점 합을 최소~최대 안에 유지 |
| H004 | 보호 | 필수 과목 | required_course_ids의 모든 과목을 포함 |
| H005 | 보호 | 제외 과목·분반 | 제외된 항목을 선택하지 않음 |
| H006 | 보호 | 고정 분반 | locked_section_ids를 반드시 유지 |
| H007 | 보호 | 허용 요일·학기 | 범위 밖 수업을 가져와 조건을 해결하지 않음 |
| H008 | 사용자 | 등교일 | exact는 정확히, max는 최대 일수로 해석 |
| H009 | 사용자 | 오전 제한 | meeting은 블록 수, day는 오전 수업이 있는 요일 수 |
| H010 | 사용자 | 점심 | 지정 창 안에서 연속 시간을 확보하고 식사 위치 모드를 유지 |
| S001 | 선호 | 공강 줄이기 | 수업 사이 총 빈 시간을 우선 최소화 |
| S002 | 선호 | 등교일 적게 | 실제 등교일 수를 우선 최소화 |
| S003 | 선호 | 고르게 듣기 | 하루 최대 실제 수업 시간을 우선 최소화 |

H003/H008/H009/H010이 사용자 조건이라고 해서 자동으로 완화 가능한 것은 아니다. 해당 요청의 완화 정책에 없거나 `allow=false`이면 그대로 유지한다. 중요도 0도 변경 허가를 대신하지 않는다.

기본 예시: 월~금 중 정확히 4일, 15~21학점, 정오 전에 시작하는 수업 블록 최대 2개, 12~14시 사이 연속 60분 식사. 이 예시가 모든 사용자의 기본 요구는 아니다.

## 5. CP-SAT 기본 변수와 제약

기호:

- s: 분반, c: 과목, d: 요일, m: 분반에 속한 고정 수업 블록.
- x_s ∈ {0,1}: 분반 선택.
- q_c ∈ {0,1}: 과목 선택.
- y_d ∈ {0,1}: 해당 요일 등교.
- a_s: 정수 배율을 적용한 학점.

### 5.1 과목·시간·학점

```text
각 과목 c:  sum(x_s for s in sections(c)) = q_c
필수 과목 c: q_c = 1
제외 과목 c: q_c = 0
제외 분반 s: x_s = 0
고정 분반 s: x_s = 1
총 학점 C = sum(a_s * x_s)
최소 학점 <= C <= 최대 학점
```

q_c가 Boolean이므로 같은 과목 분반을 여러 개 선택할 수 없다.

같은 요일에서 `start_A < end_B AND start_B < end_A`이면 충돌이다. 충돌하는 서로 다른 분반 s,t에 `x_s + x_t <= 1`을 추가한다. 분반 내부 블록끼리 겹치는 잘못된 데이터는 사전 검증한다. 한 분반에 여러 충돌 블록이 있어도 분반 쌍 제약은 중복해서 만들 필요가 없다.

고정 시간표 선택 문제이므로 분반별 Boolean과 충돌 쌍 제약으로 구현할 수 있다. OptionalIntervalVar가 필수는 아니다. 어떤 표현을 쓰든 모든 수업 블록이 같은 x_s에 연결되어야 한다.

### 5.2 등교일

그날 수업이 있는 분반 집합을 A_d라 하면 다음 양방향 관계를 만든다.

```text
모든 s ∈ A_d에 대해 x_s <= y_d
y_d <= sum(x_s for s in A_d)
A_d가 비어 있으면 y_d = 0
```

등교일은 `sum(y_d)`다. exact=4이면 `sum(y_d)=4`, max=4이면 `sum(y_d)<=4`다. 허용하지 않은 요일에 블록이 하나라도 있는 분반은 x_s=0으로 제한한다.

### 5.3 오전

`before_minute=720`이라면 12:00 시작은 오전에 포함하지 않는다.

- meeting: 각 분반의 오전 블록 수 b_s를 미리 계산하고 `sum(b_s*x_s) <= limit`.
- day: 해당 요일에 오전 수업이 있는 분반들의 OR 변수 u_d를 만들고 `sum(u_d) <= limit`.

동일 과목이 같은 날 오전에 두 번 수업하면 meeting=2, day=1이다. 완화 시에는 limit만 조정하며 경계나 집계 단위를 바꾸지 않는다.

### 5.4 점심 — 정확한 연속 시간

식사 창 [W_start,W_end)와 길이 L에 대해 가능한 정수 분 시작 t를 W_start부터 W_end-L까지 고려한다. 12~14시, L=60이면 12:00~13:00 사이의 61개 시작점이다. 15분 간격만 시험하는 근사는 기본 규칙을 만족하지 않는다.

요일별 식사 후보 [t,t+L)에 대응하는 Boolean w_{d,L,t}를 둔다.

1. 등교일에는 하나의 식사 구간을 선택하고 공강 요일에는 선택하지 않는다: `sum(w_{d,L,t}) = y_d`.
2. 식사 후보와 겹치는 수업이 있는 분반 s에 대해 `w_{d,L,t} + x_s <= 1`.
3. between_classes에서는 해당 w가 참일 때 식사 전 종료하는 선택 수업이 하나 이상, 식사 후 시작하는 선택 수업이 하나 이상 있어야 한다.
4. within_window에서는 3번을 추가하지 않아 첫 수업 전·마지막 수업 후 식사도 허용한다.

between_classes의 존재 검사는 해당 조건에 맞는 블록을 가진 분반 ID 집합의 선택 합 >=1로 표현한다. 식사 전후 수업이 같은 과목에 속할 필요는 없다. 해당 집합이 비어 있으면 그 식사 후보 w=0이다.

완화로 L이 여러 값이면 8절의 길이 선택 변수 z_{lunch,L}와 연결한다: `w_{d,L,t} <= z_{lunch,L}`. 모든 길이·시작 후보에 대한 합이 y_d가 되도록 한다. 원래 60분 제약을 무조건 남겨둔 채 45분 제약만 추가하면 완화가 되지 않으므로, 선택한 길이에 대응하는 식사 후보로 모델링한다.

식사 Boolean은 해의 존재를 보장하는 보조 변수다. 표시할 식사 구간은 선택된 수업을 다시 확인해 가장 이른 유효 구간으로 결정한다. 솔버가 임의로 선택한 점심 시작점 차이를 서로 다른 시간표로 세지 않는다.

## 6. 모델 안에서 계산할 지표

수업 간 공강을 최소화하려면 CP-SAT 목표에도 정확한 빈 시간 지표를 연결해야 한다.

요일별로 다음을 계산한다.

```text
teaching_d = sum(그 요일의 분반 s 실제 수업 분 수 * x_s)
span_d = last_end_d - first_start_d
gap_d = span_d - teaching_d
total_gap = sum(gap_d)
max_daily_teaching = max(teaching_d)
latest_end = max(last_end_d)
```

시간 중복 금지가 보장되므로 span에서 실제 수업 시간을 빼면 내부 빈 시간 합이 된다. 공강 요일은 first_start_d=last_end_d=0으로 둔다. 같은 과목의 15분 휴식과 수업 사이 점심도 gap에 포함하며, 첫 수업 전·마지막 수업 후는 제외한다.

구현 예: 선택된 블록의 start, 미선택 블록의 1440을 모아 min을 취해 first_raw를 만든다. y_d=1일 때 first_start_d=first_raw, y_d=0일 때 0으로 연결한다. last_end_d는 선택 블록의 end, 미선택 블록의 0의 max다. 해당 요일에 블록 자체가 없으면 두 값을 0으로 고정한다.

이들 집계는 AddMinEquality/AddMaxEquality 및 조건부 등식 등으로 모델에 연결한다. 결과 처리 단계에서도 별도로 재계산하여 모델과 일치하는지 확인한다.

## 7. 선호 목표 — 사전식 최적화

모든 목표는 작은 값을 우선한다.

| profile | 비교 순서 |
|---|---|
| compact | total_gap → latest_end → max_daily_teaching → morning_meeting_count → 정렬된 분반 ID 목록 |
| fewer_days | attendance_days → total_gap → latest_end → 정렬된 분반 ID 목록 |
| balanced | max_daily_teaching → total_gap → latest_end → 정렬된 분반 ID 목록 |

정확히 4일 등교 조건이면 fewer_days의 첫 지표는 모두 동일하다. balanced는 현재 실제 수업 시간의 최대치를 줄이는 뜻이며 과제·난이도 분산을 검증했다는 뜻은 아니다.

앞 목표의 우선순위를 보장하려면 한 목표씩 CP-SAT으로 최소화하고, **최적값이 증명된 단계만** 그 값으로 고정한 다음 다음 목표를 최적화한다. 임의의 큰 가중치로 서로 다른 우선순위를 섞지 않는다.

정수 목표와 최적성 증명이 필요한 설정에서는 relative_gap_limit=0, absolute_gap_limit=0을 사용한다. 시간 제한으로 FEASIBLE이면 현재 유효 후보는 반환할 수 있지만 그 목표값을 증명된 최적값으로 고정하여 전체 사전식 최적을 주장하지 않는다. 누적 시간 예산과 단계별 상태·값·best bound를 기록한다.

최소 변경 수 같은 앞 단계가 증명되고 뒤의 선호 단계에서 중단되면, 증명된 단계의 범위만 따로 표시한다. 모든 지표의 최적성을 하나의 불명확한 Boolean으로 섞지 않는다.

ID 동률은 현재 코드와 같은 정렬된 ID 목록의 사전식 순서를 따른다. seed 고정만으로 이 순서가 보장된다고 가정하지 않는다. ID 합계 최소화도 같은 의미가 아니다. 필요하면 수치 목표를 고정한 모델에서 가장 작은 가능한 ID 접두사를 순차적으로 찾는다. 접두사 자체로 해가 되면 더 긴 목록보다 먼저 선택하고, 아니라면 다음 가능한 최소 ID를 확장한다. 각 더 작은 접두사가 불가능함을 확인하지 못하면 해당 동률 순위의 증명을 주장하지 않는다.

학점별 대표안은 목표 학점마다 보호된 `총 학점=목표` 조건을 추가한 별도 실행이다. 15·18·21학점 대표안을 전역 점수순 Top-3라고 부르지 않는다. 학점 범위만 입력했다고 최대 학점이나 최소 학점을 자동으로 더 선호하지 않는다.

## 8. 최소 조건 완화도 CP-SAT으로 계산

### 8.1 진입 조건

먼저 원래 조건 모델을 푼다.

- 해가 있으면 원래 조건 결과를 반환한다. 변경 수 0.
- 원래 모델이 INFEASIBLE이고 완화 정책이 활성화되어 있으면 완화 모델로 이동한다.
- UNKNOWN 또는 실행 오류이면 원래 조건이 불가능하다고 단정하여 자동 완화 단계로 넘어가지 않는다. 중단·오류 상태를 반환한다.

최소 변경 수 0도 포함하는 단일 모델로 같은 의미를 구현할 수는 있으나, 원래 조건 가능 여부와 증명 상태를 구분할 수 있어야 한다. 팀 MVP의 권장 흐름은 원래 조건 모델 후 완화 모델이다.

### 8.2 완화 변수

완화 항목 g별로 원래 값과 허용 값의 집합 L_g를 만든다. 중복 값은 제거하며 원래 값을 포함한다.

```text
z_g,l ∈ {0,1}: 항목 g에서 값 l 선택
각 항목 g: sum(z_g,l for l in L_g) = 1
r_g = 1 - z_g,original
sum(r_g) <= max_changed
```

보호 항목, 정책에 없는 항목, allow=false인 항목은 원래 값만 허용한다. z가 선택된 경우에만 해당 값의 등교일·오전 상한·학점 범위 제약이 활성화되도록 조건부 제약을 만든다. 점심은 5.4절의 식사 후보 변수를 해당 길이 선택 z에 연결한다.

예: 오전 상한 2,3,4 중 하나를 선택할 때, 항상 `morning_count<=2`를 추가하고 나머지 제약을 덧붙이는 구현은 잘못이다. 각 상한은 대응 z가 참일 때만 적용한다.

### 8.3 조정 정책

| 항목 | 허용 방향·단위 | 변경할 수 없는 것 |
|---|---|---|
| attendance_days | exact: 명시한 목표값, max: 상한 증가. 1일 단위 | exact/max 모드, 허용 요일 |
| morning_limit | 상한 증가. 요청에 선언한 1회 또는 1일 단위 | 오전 경계, meeting/day 단위 |
| credit_range | 범위 확대. 예제는 3학점 단계 | 필수 과목, 보호된 총 학점 고정 조건 |
| lunch_duration | 길이 감소. 예제는 15분 단계, 최소 45분 등 | 식사 창, within_window/between_classes |

학점 하한과 상한은 하나의 credit_range 그룹이다. 양쪽을 바꿔도 변경 조건 수는 1이며 변경량은 두 확대량을 더한다. 지정 단계에 맞지 않거나 허용 방향을 벗어난 정책은 입력 오류로 처리한다.

예제 정책은 규칙 파일의 `example_relaxation_policy`를 참고한다. 예제 값을 실제 사용자에게 자동 적용하지 않는다. 사용자 허용이 없는 요청은 rules가 비어 있어야 한다.

### 8.4 완화 목표

각 값 l의 변경 정도 u_g,l을 정책 step으로 정확히 계산한다.

```text
F1 = sum(r_g)
F2 = sum(importance_g * r_g)
F3 = sum(u_g,l * z_g,l)

사전식 최소화: F1 → F2 → F3 → 기존 선호 목표
```

- 등교일·오전·점심: 원래 값과의 절댓값 차이 / step.
- 학점 범위: (하한을 낮춘 양 + 상한을 높인 양) / step.
- F1~F3은 정확한 정수 목표다. step으로 나누어 정수가 되지 않는 허용 단계는 입력 검증에서 처리한다.
- 중요도가 높을수록 변경하지 않기를 선호한다. 절대 변경 금지와 높은 중요도는 다르다.
- 이 정책에서는 중요한 조건 하나를 바꾸는 안이 덜 중요한 조건 두 개를 바꾸는 안보다 우선할 수 있다. 조건 수 우선이라는 정의이며 R011이 이를 검사한다.

F1 최적값을 증명하고 고정한 후 F2, 다시 F3를 푼다. 각 단계의 목표·실제 값·상태·bound를 기록한다. F1~F3 전체가 증명된 범위에서만 완화 비용의 최소성을 주장한다. 뒤의 선호 정렬이 중단되면 최소 완화 증명과 추천 순위 증명을 분리한다.

assumptions/불가능 원인 집합은 진단에 활용할 수 있지만 반환된 원인 집합을 곧바로 최소 변경 조건 집합으로 간주하지 않는다. 이 룰베이스의 최소 완화는 F1~F3 최적화로 결정한다.

## 9. Top-K: 서로 다른 분반 집합을 CP-SAT으로 반복 탐색

한 시간표의 선택 분반 집합을 S, 전체 모델의 분반 집합을 U라 하면 다음 제외 제약을 추가한다.

```text
sum(1-x_s for s in S) + sum(x_s for s in U-S) >= 1
```

이 식은 **정확히 그 분반 집합 하나**를 제외한다. 과목 수가 바뀔 수 있는 문제에서 `sum(x_s for s in S) <= |S|-1`만 쓰면 S를 포함하는 더 큰 시간표까지 제외하므로 기본 규칙으로 사용하지 않는다.

각 순위에서는 다음을 수행한다.

1. 기본 제약과 앞서 선택한 시간표들의 제외 제약으로 모델을 구성한다.
2. 해당 순위의 사전식 목표를 CP-SAT으로 최적화한다.
3. 선택 분반 집합과 결과를 저장한다.
4. 다음 순위에서는 앞 순위에서 임시로 고정했던 선호 최적값을 제거하고 다시 최적화한다.

첫 시간표의 최소 빈 시간 값을 모든 후속 탐색에 고정해버리면 다음으로 좋은 시간표를 놓칠 수 있다. 기본 모델을 다시 만들거나, 단계별 고정을 분리해 관리한다.

최소 완화 추천의 기본 출력 범위는 `minimum_cost_only`다. 한 번 증명한 F1~F3 최적 벡터는 전체 출력의 범위 조건으로 유지하고, 그 안에서 선호 기준 Top-K를 찾는다. 이때 유지해야 하는 완화 비용 고정과 매 순위마다 다시 풀어야 하는 선호 목표 고정을 구분한다. K개가 부족해도 비용이 더 나쁜 조정안을 자동으로 채우지 않는다.

각 순위의 증명이 완료되지 않으면 현재 후보를 유효한 부분 결과로 반환할 수 있지만 전역 Top-K라고 주장하지 않는다. 원래 조건이 가능한데 K개보다 적다는 이유로 완화를 자동 실행하지 않는다.

### 시간표 개수와 보조 변수 해 개수의 구분

점심 구간 등 보조 변수 값만 다른 해는 같은 시간표다. `enumerate_all_solutions`의 콜백 횟수를 곧바로 시간표 개수로 사용하지 않는다.

676개 회귀 검증 같은 전수 모드에서는 선호 목적함수를 제거하고, 매번 CP-SAT으로 하나의 분반 집합을 찾은 뒤 위 제외 제약을 추가한다. 마지막 남은 모델이 INFEASIBLE일 때 해당 범위의 분반 집합 전수 탐색 완료로 기록한다. 중간 중단이면 얻은 수는 전체 개수가 아닌 하한/현재 발견 수다.

마지막 제외 모델의 INFEASIBLE은 '더 이상의 시간표 없음'이지 최초 사용자 요청이 불가능하다는 뜻이 아니다. 이미 얻은 후보를 보존한다.

## 10. 수강신청 실패 대체안

실패한 분반을 x_s=0으로 제외하고 원래 보호 조건을 유지한다. 실패 분반이 고정 분반이기도 하면 입력 모순을 반환하며 고정을 임의로 해제하지 않는다.

- 기본 정책: 기존 과목 집합을 정확히 유지한다. 기존 과목 q=1, 그 밖의 과목 q=0.
- preserve_credit_total=true이면 기존 총 학점을 정확히 유지한다. 원래 15~21 범위였다고 18학점을 21학점으로 자동 변경하지 않는다.
- allow_course_replacement=true인 명시적 요청에서만 과목 집합 변경을 허용한다. 원래 필수 과목은 계속 유지한다.

기존 과목 집합 Bc, 기존 분반 집합 Bs에 대해 CP-SAT 목표를 만든다.

```text
course_changes  = sum(1-q_c for c in Bc) + sum(q_c for c not in Bc)
section_changes = sum(1-x_s for s in Bs) + sum(x_s for s not in Bs)

사전식 최소화: course_changes → section_changes → 기존 선호 목표
```

대칭차 원소 수이므로 하나를 빼고 하나를 넣으면 값은 2다. 사용자에게 '2과목 교체'로 오표기하지 말고 제거·추가 목록과 동일 과목 분반 교체 쌍을 반환한다.

기본 대체안 함수는 최소 조건 완화를 자동으로 켜지 않는다. 두 기능을 합친 별도 요청을 지원할 때는 완화 F1~F3 → 과목 변경 → 분반 변경 → 선호 순서를 명시하고, 고정된 과목·분반·학점은 완화 대상에서 제외한다. 복합 모드를 제공하지 않으면 미지원으로 명확히 안내한다.

## 11. 상태·증명·시간 예산

| 실제 CP-SAT 상태 | 서비스 해석 |
|---|---|
| OPTIMAL | 해당 실행의 최적성 또는 성공 의미를 목적함수·설정과 함께 해석. 전체 시간표 열거 완료와 동일하지 않음 |
| FEASIBLE | 유효한 해 존재. 해당 목표의 최적성을 입증했다고 주장하지 않음 |
| INFEASIBLE | 현재 모델과 범위의 해 없음. 최초 모델인지, 제외 제약을 추가한 잔여 모델인지 구분 |
| UNKNOWN | 제한 등으로 판정을 완료하지 못함. 불가능으로 변환 금지 |
| MODEL_INVALID | 모델 오류. 정상적인 후보 없음으로 변환 금지 |

라이브러리 미설치·worker 실행 실패는 `ENGINE_UNAVAILABLE` 또는 기존 계약의 명시적 실행 오류로 처리한다. 솔버 상태를 임의로 만들어 넣지 않는다.

요청 전체에 하나의 시간 예산을 적용한다. 원래 조건, 완화 단계, 사전식 목표, Top-K 반복이 같은 예산을 공유한다. 각 solve에 남은 시간을 전달하고 노드 어댑터의 전체 실행 제한도 설정한다. 정상적인 제한 종료에서는 확보한 해를 보존한다. worker 강제 종료로 결과를 받지 못했다면 받지 못한 해를 반환했다고 주장하지 않는다.

최소 기록 항목:

```text
engine, engine_version, model_build_id
catalog_version_or_hash, normalized_request, mode
original_constraints, effective_constraints, changes
phase_results: stage, raw_status, objective_value, best_bound, elapsed
proven_objective_prefix, minimality_proven, ranking_proven
coverage: partial | exhaustive
termination_reason
returned_unique_count, total_unique_count_or_null
recommendations, diagnostics, warnings
```

K개를 최적으로 구했다고 coverage=exhaustive가 되는 것은 아니다. 정렬 최적성과 전체 후보 열거 여부를 따로 표시한다. 한 phase의 상태만 가지고 요청 전체 성공·실패를 결정하지 않는다.

## 12. 설명·비교·표시 규칙

- 추천 이유는 실제 선택 결과의 지표로 만든다. '금요일 공강', '오전 수업 없음'의 근거를 반환한다.
- 수업 전 식사를 수업 사이 식사라고 표시하지 않는다.
- 완화 결과에는 원래 값과 조정 값, 변경 수, 변경하지 않은 조건 충족 여부를 함께 표시한다.
- 원래 요청과 선택된 시간표를 자동 덮어쓰지 않는다.
- Node.js에서 재검증한 지표가 worker의 모델 지표와 다르면 통합 오류로 다룬다.
- 확인되지 않은 강의평·과제·진로·난이도·이동시간을 0점 또는 최고점으로 만들어 넣지 않는다.

| 연강 수 | 허용 간격, 같은 과목 내부 블록 포함 여부 |
| 원하는 공강 요일 | 특정 요일 금지인지 공강 선호 가중치인지 |
| 교수 선호·강의평 | 교수 ID, 출처·값의 범위·누락 처리 |
| 과제·시험 부담 | 비교 가능한 데이터와 평가 단위 |
| 수업 간 텀 | 목표 간격, 긴 공강 기준과 페널티 |
| 희망 등하교 시각 | 요일별 허용 시간창 또는 선호 목표 |
| 진로 연관 수업 | 과목별 진로 태그와 점수 정의 |
| 전공/교양 비율 | 학점 기준인지 과목 수 기준인지 |
| 어려운 수업 분산 | 신뢰할 수 있는 난이도 값과 요일별 집계 |
| 이동 부담 | 건물·거리 또는 이동시간 행렬과 실제 이동 가능한 최소 간격 |

이미 팀 코드가 지원하는 항목은 보존한다. 위 항목 전체를 이번 문서만으로 구현·검증 완료라고 표시하지 않는다. 추가 가중치가 들어가면 정수 척도와 우선순위를 별도로 합의한다.

## 14. 인수 검증

기존 핵심 100개, 추가 테스트, 실제 CSV 회귀, R001~R030·I031~I040 및 현재 코드의 추가 완화 테스트를 유지한다. 실제 보유 스위트의 수집/실행/통과 수를 보고한다.

`ortools_acceptance.json`의 ORT001~ORT014는 OR-Tools 전환에 특화된 추가 확인 항목이다. 생산 호출 경로는 실제 CP-SAT을 사용해 검사하며, 상태 매핑/오류 경계의 테스트 대역은 실제 엔진 통합 검사와 구분한다.

실제 원본 CSV 회귀는 같은 해시·범위·조건에서만 676개(15학점 524, 18학점 140, 21학점 12)를 기대한다. 새 원본이나 확대된 범위에도 같은 숫자를 강요하지 않는다. 원래 단계별 전처리 통과 수는 알고리즘 구조가 바뀌면 달라질 수 있으며, 최종 고유 시간표 집합과 제약 만족을 비교한다.

팀원에게 전달할 완료 보고에는 다음이 있어야 한다.

1. 실제 엔진 버전, 실제 모델/solve 경로와 의존성.
2. 정상 추천·최소 완화·대체안의 입력/출력·단계별 상태 로그.
3. Node.js 함수 → worker → CP-SAT → 결과 분석까지 실행한 통합 결과.
4. 재실행 명령, 회귀 결과, 시간 제한 시 동작.
5. 남은 미지원 기능과 미검증 범위.
