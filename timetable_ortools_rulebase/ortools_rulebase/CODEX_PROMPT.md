# OR-Tools 룰베이스 적용 요청

현재 Node.js 시간표 추천 코드가 첨부한 OR-Tools 룰베이스를 만족하도록 전환해줘. 이 요청의 필수 완료 조건은 **실제 운영 추천·대체안·최소 완화 탐색에서 OR-Tools CP-SAT을 사용하는 것**이야.

먼저 저장소의 AGENTS.md, README, CONTRACT.md, 기존 함수와 제공자, 의존성·테스트를 확인해줘. 그다음 이 패키지의 README.md, rulebase.json, ortools_acceptance.json을 전체 읽어줘. 기존 기능과 작업 중인 변경을 보존하면서 필요한 엔진·연결 부분을 구현해줘.

## 실행 구조

- 기존 Node.js의 지표·설명·비교·CLI를 최대한 유지해줘.
- Python 공식 OR-Tools CP-SAT worker와 Node.js OrToolsCandidateProvider 어댑터를 연결해줘. 이미 팀의 실제 OR-Tools 엔진이 있다면 그 엔진을 같은 의미로 연결해도 돼.
- 정상 추천, 수강신청 실패 대체, 최소 조건 완화 경로를 모두 실제 CP-SAT 모델과 solve로 연결해줘.
- 평가·설명만 하는 순수 함수까지 불필요하게 외부 엔진을 호출하게 만들지는 마.
- import만 추가하거나 기존 전수 탐색 결과를 솔버에 형식적으로 통과시키는 구현은 요구사항을 충족하지 않아.
- 엔진 장애 시 DemoCandidateProvider로 조용히 대체하지 마. 명시적인 엔진 오류를 반환해줘.
- 설치한 실제 버전을 기록하고 검증 후 의존성을 고정해줘. 특정 버전을 추측하지 마.

## 모델링

분반 선택 x_s, 과목 선택 q_c, 등교일 y_d를 만들고 H001~H010을 구현해줘. 모든 수업 블록을 같은 분반 변수에 연결하고 학점을 중복 합산하지 마.

시간은 정수 분으로, 학점은 정확한 배율의 정수로 표현해줘. 겹치는 분반 쌍은 동시 선택을 금지하고, 학점·등교일·오전 제한·식사 구간 조건을 모델에 넣어줘.

점심은 선택된 전체 수업과 충돌하지 않는 연속 구간으로 모델링해줘. within_window와 between_classes의 의미를 유지하고, 길이 선택 변수를 식사 후보 구간에 연결해줘. 15분 간격만 시도하거나 원래 60분 제약을 남긴 채 45분 제약을 덧붙이지 마.

원래 조건으로 불가능하다고 증명된 경우에만 허용한 완화 모델로 진행해줘. 보호 조건은 유지하고 다음을 CP-SAT의 사전식 목표로 최소화해줘.

1. 변경 조건 그룹 수
2. 변경한 조건의 중요도 합
3. step 기준 변경량 합
4. 기존 선호 목표

앞 목표의 최적값을 증명한 경우에만 고정하고 다음 목표로 넘어가줘. FEASIBLE/UNKNOWN을 최적 또는 불가능으로 과장하지 마. 입증된 목표의 범위를 별도 기록해줘.

대체안은 실패 분반을 제외하고 원래 필수·고정 조건을 유지하며, 과목 집합 변경 → 분반 집합 변경 → 선호 순으로 CP-SAT에서 최적화해줘. 기존 과목 유지·학점 유지 정책을 보존해줘.

## Top-K와 전수 검증

문서의 정확한 분반 집합 제외식을 사용해줘. 선택된 분반만의 합을 제한하여 상위집합까지 제외하지 마.

다음 순위를 탐색할 때 이전 순위에서 임시 고정한 선호 최적값을 제거하고 다시 최적화해줘. 최소 완화 모드에서 전체 출력 범위로 고정한 최적 완화 비용과 이 임시 고정을 구분해줘.

점심 시작점 같은 보조 변수만 다른 해는 같은 시간표야. 총 후보 개수를 셀 때는 분반 집합 기준으로 세고, 완료 여부를 명시해줘. K개 반환을 전체 후보 전수 탐색 완료로 표시하지 마.

원래 점심·오전 조건으로 잘라낸 후보 목록이 아닌 기준 카탈로그에서 완화 탐색을 시작해줘. 요청 전체의 시간 예산을 관리하고, 단계마다 시간을 무한히 재설정하지 마.

## 연결·검증

기존 호출부와 테스트에 맞는 어댑터를 작성해줘. 필요한 ranking/selection/relaxation_policy/baseline/search_options가 worker까지 전달되게 해줘. 동기/비동기 계약이 바뀌면 호출부와 문서에 명시해줘.

기존 테스트와 회귀를 보존하고 실제 CP-SAT 제공자를 연결해 실행해줘. 기존 테스트가 Demo 제공자에만 연결되어 있다면 엔진 통합 검증을 추가해줘.

R001~R030, I031~I040 자료가 있으면 동일 의미로 재검증해줘. ortools_acceptance.json의 ORT001~ORT014도 검증하고 실제 엔진 실행과 상태 매핑용 테스트 대역을 구분해줘.

기존 CSV와 동일한 범위·조건일 때만 고유 시간표 676개를 회귀 기준으로 사용해줘. 파일이 없으면 합성 데이터로 실제 CP-SAT 경로를 검증하고 실제 데이터 검증 미실시를 밝혀줘.

계획으로 끝내지 말고 엔진 구현·연결·실제 실행·오류 수정·문서화까지 진행해줘. 프론트나 DB가 없어도 진행해줘.
