# 숭실대 건물 간 도보 시간

**먼저 `walk.html`을 더블클릭하세요.** 압축을 푼 뒤 Chrome이나 Edge에서 열면 바로 사용할 수 있습니다. 설치가 필요하지 않습니다. 네이버 지도 길찾기에는 인터넷 연결이 필요합니다.

## 들어 있는 값

| 항목 | 제공 범위 |
| --- | --- |
| 캠퍼스 | 숭실대 서울캠퍼스 공식 건물 01~24. 대운동장(25)은 운동장으로 분류해 제외 |
| 방향별 구간 | 552개. 24개 건물에서 자기 건물을 제외한 23곳으로 가는 경로 |
| 네이버 지도 확인값 | 최초 0개. 직접 확인한 방향만 저장하며 역방향은 별도 |
| 공개 보행로 추정값 | 552개. 일반 추정 446개, 우회 확인 필요 104개, 건물 접근점 확인 필요 2개 |
| 강좌 자료와 대조 | 프로젝트 2026-2 강의실에서 건물 이름을 판독할 수 있는 15개 건물을 모두 포함. ‘한경직기념관 소예배실’은 한경직기념관으로 연결 |

## 네이버 지도에서 기록하기

1. 출발과 도착을 선택하고 **네이버 지도 열기**를 누르세요. 휴대폰에서는 **모바일 앱 열기**도 쓸 수 있습니다. 웹 링크가 길찾기 화면만 열면 도보를 선택하고 두 건물명을 직접 검색하세요.
2. 도보의 추천 경로에서 두 건물의 실제 이용 출입구를 확인하세요. 경로가 캠퍼스 밖으로 불필요하게 우회하거나 잠긴 통로를 지나면 이용 가능한 출입구로 옮기세요. 건물 외부 이동 시간만 기록합니다.
3. 화면에 표시된 분, 확인일, 어떤 출입구를 사용했는지 또는 경로 공유 링크를 입력해 **이 방향 기록 저장**을 누르세요. 거리는 선택 사항입니다. 앱에서 안내한 시간도 보행 예상 시간입니다.
4. **다음 미확인 구간**을 누르면 방금 저장한 경로의 역방향을 먼저 제안합니다. 이후에는 실제 강좌에서 30분 미만 이동이 가능한 분반 쌍이 많은 구간부터 제안합니다. 현재 경로를 저장하지 않고 누르면 우선순위 순서의 다음 미확인 구간으로 이동합니다.
5. **기록 백업(JSON)**을 받으면 브라우저를 바꾸거나 팀원 기록을 가져올 수 있습니다. 브라우저의 로컬 파일 저장소는 위치나 브라우저 설정에 따라 달라질 수 있으므로 백업 파일을 보관하세요. 가져오기는 방향별 최신 확인일을 유지합니다. 같은 날짜에 내용이 다르면 어떤 방향이 충돌했는지 알려줍니다.

## 시간표에서 확인하기

배포본의 `timetable-demo/public/walking-route-times.mjs`에는 공개 보행로 추정값 445개 방향이 들어 있습니다. PowerShell에서 `timetable-demo`로 이동해 `npm.cmd start`를 실행하면 아래 두 사례를 바로 확인할 수 있습니다.

추천 후보 화면은 같은 방향의 현장 실측값, 네이버 확인값, 기존 경험 안내, 공개 보행로 추정값 순으로 사용합니다. 기존 실측값은 `public/campus-walking-routes.mjs`에 기록합니다. 이번 배포 모듈에는 네이버 확인값이 0건이며, 추정값은 OpenStreetMap 출처와 함께 표시합니다. 우회·접근점 확인이 필요한 106개 방향은 추정값 내보내기에서 제외합니다.

### 실제 후보에서 확인하기

`2026-2 · AI소프트웨어학부` 기준입니다. 지정한 두 과목만 담으면 총 6·전공 6·교양 0학점입니다.

- 디지털포렌식개론과 알고리즘을 담으세요. 화·목·금, 10:00~18:00을 설정하고 세부 선호에서 **등교일이 적은 순**을 고르세요. 1번 후보에서 금요일 14:45 → 15:00 문화관 → 정보과학관의 15분 이내 경험 안내를 볼 수 있습니다.
- 데이터베이스응용과 운영체제를 담으세요. 월·화·수·목, 10:00~18:00, **내 선호 함께 반영**으로 추천을 받으세요. 1번 후보는 화요일 14:45 → 15:00, 2번은 목요일 같은 시각에 정보과학관 → 벤처중소기업센터 이동 안내가 나옵니다. 쉬는 시간 15분, 층 이동 포함 약 14분, 여유 1분입니다. 3번 후보로 바꾸면 안내가 사라집니다.

### 새 네이버 확인값을 적용하기

1. 이 폴더의 `walk.html`에서 이전 **기록 백업(JSON)**을 가져오고 새 확인값을 저장합니다.
2. 배포본의 추정값도 계속 쓰려면 **미확인 경로에 공개 보행로 추정값도 포함**을 켜세요. **프로젝트용 파일 받기**를 누르면 선택한 설정에 맞는 모듈이 내려받아집니다.
3. 받아 둔 모듈로 `timetable-demo/public/walking-route-times.mjs`를 갱신하고 시간표 화면을 새로고침하세요.

## 파일

| 파일 | 용도 |
| --- | --- |
| `walk.html` | 24개 건물 조회, 층 보정 미리보기, 네이버 길찾기, 방향별 기록, 백업 및 프로젝트 모듈 내보내기 |
| `data/routes.csv` | 엑셀에서 열 수 있는 552행의 초기 자료. 네이버와 OSM 열을 구분 |
| `data/priority-routes.csv` | 먼저 확인할 163개 방향. 2026-2 AI소프트웨어학부 조회 범위(교양 포함)에서 0~29분 간격이 가능한 서로 다른 분반 쌍 수로 정렬 |
| `data/osm-minute-matrix.csv` | 24×24 공개 보행로 추정 분표. 행이 출발, 열이 도착. 주의 구간 상태는 routes.csv에 수록 |
| `data/campus-walk.json` | 초기 경로와 건물 기준점 좌표·건물 번호·OSM 식별자·품질 표시 |
| `source/pedestrian-graph.json` | 공개 보행로를 가공한 단방향 간선 자료. 노드 ID와 두 지점 간 미터 |
| `source/verify-audit.py` | 동봉된 그래프에서 최단거리를 재계산해 552개 거리·시간·주의 표시를 검증 |

CSV와 기본 JSON은 최초 배포 시점의 자료입니다. `walk.html`에서 새로 확인한 기록은 브라우저, JSON 백업 및 내보낸 프로젝트 모듈에 반영됩니다.

## 먼저 확인할 구간

문화관 → 정보과학관은 이 학기 자료에 30분 미만 간격이 가능한 분반 쌍이 68개입니다. 진리관 → 조만식기념관은 805개입니다. 같은 요일에 두 강좌가 연속 배치될 수 있고 학기 중 다른 수업시간이 서로 겹치지 않는 서로 다른 과목·분반 조합을 방향별로 한 번씩 셌습니다. 이 숫자는 조회 자료에 들어 있는 조합 수로, 실제 수강 인원이나 추천 빈도를 뜻하지 않습니다. 학과·학기·교양 개설 자료가 바뀌면 우선순위도 달라집니다.

## 계산 기준과 출처

건물 번호·이름은 숭실대 공식 캠퍼스맵을, 건물 외곽과 보행로는 2026-11-20에 내려받은 OpenStreetMap 자료를 기준으로 했습니다. `campus-walk.json`에 원본 추출 URL과 SHA-256을 담았습니다. 프로젝트에서 실제로 사용되는 5자리 강의실 번호와 맞도록 학교의 01~24 번호를 사용했습니다. [숭실대학교 캠퍼스맵](https://ssu.ac.kr/학교소개/캠퍼스안내/캠퍼스맵/?team=건물)

건물마다 학교 지도 표식 부근에서 건물 외곽선과 연결된 보행로 끝점 또는 인근 보행로 위의 접근점 한 곳을 골랐습니다. 가까운 외벽 지점과 접근점 사이의 짧은 연결 거리(0~12.1m)도 포함합니다. 이 지점은 실제 개방 출입구와 다를 수 있습니다. 통행 가능한 보도·계단·보행로, 소규모 생활도로 등을 연결하고 접근 제한이 표시된 길을 제외했습니다. 도보 일방통행을 반영한 그래프에서 다익스트라로 최단거리를 구한 뒤, 분당 75m를 가정해 분 단위로 올림했습니다. 비, 혼잡, 신호 대기, 오르막, 엘리베이터 대기, 실내 지름길과 무장애 경로는 계산에 포함하지 않았습니다. 도보 방향은 따로 저장하며, 같은 추정 시간이 반복될 수 있습니다.

보행로 길이가 150m를 넘고 보행로 양 끝의 직선거리보다 3배 넘게 길면 `detour_review`, 두 건물이 사실상 같은 보행로 지점(망 안에서 1m 미만)을 쓰면 `shared_access`입니다. 나머지 `modeled`도 기하학적 추정치입니다. 경사·계단이 많은 숭실대에서는 많이 쓰는 동선의 실제 보행 기록이 쌓일수록 개선할 수 있습니다. 원본 데이터와 여기서 파생한 보행 그래프·좌표·경로 추정표는 © OpenStreetMap contributors, ODbL 1.0입니다.
