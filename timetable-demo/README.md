# 시간표 추천 데모

처음 한 번 `npm run setup:solver`로 OR-Tools를 설치한 뒤 상위 폴더의 **시간표 데모 시작.bat**를 더블클릭하면 터미널 하나에서 실행됩니다. 서버가 준비되면 **크롬 새 창**이 자동으로 열립니다. 기본 추천은 Codex 연결 없이 사용할 수 있습니다.

**종료: 터미널 창 닫기 또는 Ctrl+C.** 서버와 이 데모의 Codex 연결 프로세스가 함께 종료됩니다. 크롬 창은 자동으로 닫지 않습니다. 기존 VBS 파일도 같은 BAT를 실행합니다.

1. **내 시간표 만들기** → 필수 과목 선택 또는 진로에서 관심 과목 찾기
2. **생활 패턴 정하기** → 학점·요일·시간 설정 → **추천 시간표 보기**
3. 등교일·하루 수업량·공강 기준의 실제 후보 비교 → **이 시간표로 정하기** → 학기 저장

**더 세밀하게 설정하기**에서 하루 수업량, 점심·연강 선호, 총/전공/교양 학점 범위를 조정할 수 있습니다. **과목 고르기**에서 특정 과목을 필수 포함하거나 제외합니다. 관심 과목은 조건에 맞으면 우선 추천하고, 담은 관심 과목을 개별 해제할 수 있습니다.

세부 설정에는 엄격한 추천 기준과 **반드시 지킬 생활 조건**도 있습니다. 등교일 정확히/최대, 오전 수업 횟수/일수, 필수 연속 점심시간을 설정합니다. 불가능 판정 후 **허용할 변경 범위 고르기**로 선택한 항목만 최소 완화합니다. 수업 상세의 **이 분반 대신 다른 분반 찾기**는 같은 과목·총 학점을 유지하는 대체안을 찾습니다. 결과를 저장하기 전까지 원래 조건과 학기 일정은 바뀌지 않습니다.

AI 추천은 생활 패턴 화면의 **문장으로 요청하고 싶다면**에서 사용합니다. 이 화면에 진입하면 기존 Codex 로그인 상태를 확인하며, 연결이 필요한 경우 **Codex 연결**을 누릅니다. 요청 예: “수요일만 등교하고 전공 6학점, 교양 2학점으로 골라줘.” 로그인 취소는 기존 계정을 로그아웃하지 않습니다.

## 화면 구성과 구현

- [Figma 디자인](https://www.figma.com/design/8MiEDoEzXnAhiSUr9oiGdF?node-id=0-1)을 모바일 중심으로 구현했습니다. PC 주요 화면은 왼쪽 내비게이션과 시간표·비교 패널을 제공합니다.
- 차콜·블루와 과목별 세이지·라벤더·블루·피치·샌드 색상, 흰 카드와 미세한 그림자를 사용합니다. 그라데이션은 없습니다.
- 기존 HTML/CSS/JavaScript와 Node 서버를 유지하며, 추천 계산은 Python의 OR-Tools 9.15.6755를 사용합니다. LMS 연결은 공통 파서의 Cheerio·Playwright를 사용합니다. 아이콘은 Figma의 SVG, 글꼴은 로컬 Noto Sans KR 400·500·700입니다. 글꼴 라이선스는 `public/assets/OFL-NotoSansKR.txt`에 있습니다.
- `public/app.js`: 단계별 화면·탐색·API 연결. `public/ui.js`: 공통 UI·시간표·비교안 선택. `public/style.css`: 모바일·PC 스타일. `public/planner.js`: 기존 저장 형식을 유지하는 브라우저 저장소.
- 추천 실패·빈 결과·진행 중 화면, 키보드 모달 닫기, 화면 읽기용 레이블, 동작 줄이기 설정을 지원합니다.
- 화면 진입·추천안 전환·탭 이동·과목 선택·모달·알림에 짧은 애니메이션을 적용했습니다. 기기의 동작 줄이기 설정을 따르면 모션을 끄며, 과목 선택 시 키보드 포커스와 스크롤 위치를 유지합니다. 모바일의 내용 영역과 하단 버튼을 분리해 버튼이 내용을 가리지 않도록 했습니다.

## 데모 범위

- **진로에서 과목 찾기:** AI·컴퓨터비전 / 데이터 분석 / 웹·백엔드 → 기초·핵심·심화 선택 → 이수 과목 체크 → 관심 과목 적용. 예시 매핑이며 공식 선수과목이나 수강 자격을 판정하지 않습니다. 외부 검색·RAG는 미구현입니다.
- **학기 캘린더:** 추천 시간표의 학기 시작·종료일을 입력해 최대 31주까지 수업을 생성합니다. 초기 날짜는 예시이며 학교 학사일정을 직접 확인해야 합니다. 휴일·휴강은 자동 반영하지 않습니다.
- **내 LMS 일정:** 학교 연결 → 과목 선택 → 일정 가져오기. 시간표 없이도 개인 과제·시험·강의 마감과 학교 캘린더 일정을 표시합니다. 마감은 한국 시간의 한 시점으로 표시하고 수업 충돌에서 제외하며, 종일·여러 날 일정을 지원합니다. LMS 일정은 원문을 여는 방식으로 확인하고 학교의 변경 사항은 다시 가져와 반영합니다.
- 수업 클릭 시 **이번 일정만 / 같은 요일 수업의 이후 일정도**를 구분해 변경합니다. 휴강·취소 표시와 복원, 날짜·시간·장소 변경, 시험·보강·개인 일정 등록 및 시간 충돌 표시를 지원합니다. 기존 수업의 종류를 시험으로 바꾸면 대체 시험, 별도 일정 추가는 추가 시험입니다.
- **수강 경험:** 가상 조합 3개에서 관심 과목을 적용하고, 저장한 시간표(없으면 현재 추천안)와 함께 선택 이유를 기록합니다. 실제 선배 후기나 공개 게시판은 제공하지 않습니다.
- **ICS 다운로드:** 활성 일정을 한국 시간 기준으로 UTC 변환해 내보냅니다. 휴강·취소는 제외합니다. 파일 생성·시간 변환·한글 줄바꿈을 검증했으며 외부 캘린더 자동 동기화는 구현하지 않았습니다. 변경 후 다시 내보내야 하며 반복 가져오기는 중복 일정을 만들 수 있습니다.
- 학기 일정·내 기록은 `localStorage`에 저장합니다. 서버 업로드·계정 간 공유가 없으며, 브라우저 데이터 삭제·다른 주소 또는 포트에서는 기록이 유지되지 않습니다. 새 시간표로 캘린더를 다시 만들면 기존 일정 변경·개인 일정이 초기화되므로 확인 창을 표시합니다.
- LMS 일정은 인증된 학교 사용자에서 만든 식별자로 별도 보관합니다. 다른 학교 계정으로 바꾸면 이전 계정의 일정은 보이지 않습니다. 같은 계정의 같은 일정은 갱신하고, 선택하지 않은 과목과 기존 수업·개인 일정은 유지합니다. 선택 과목의 정상 조회에서 사라진 일정만 제거하며, 부분 실패가 있으면 누락된 기존 일정을 보존합니다. 새 추천 시간표로 학기를 만들어도 LMS 기록은 유지합니다.

- AI소프트웨어학부 전공 32개·숭실대 교양 18개, 총 50과목·150개 가상 분반. 과목명·학점·이수구분은 공식 교육과정 기준이며 시간·분반·강의실은 생성한 데모 데이터입니다.
- 교양은 2026학년도 교양필수 목록에서 선택했습니다. 같은 교양 교과목군은 한 과목만 포함합니다. 전공 학점에는 전공기초·전공필수·전공선택을 포함합니다.
- 학년·실제 개설 학기·선수과목·수강 대상·기이수 내역·졸업 요건은 판정하지 않습니다. 분야 태그는 추천 시연용 분류입니다.
- 선택 과목당 한 분반, 모든 수업 시간 충돌, 가능한 요일·시작/종료 시간, 학점 범위, 필수 포함·제외를 검사합니다. 인접한 수업의 종료·시작이 같으면 시간 충돌로 보지 않으며 건물 간 이동 시간은 계산하지 않습니다.
- 실제 CP-SAT 모델로 추천·대체·완화를 계산합니다. 엄격한 사전식 순위, 분반 집합 단위 중복 제거, 학점별 독립 대표안과 제한된 전수 열거를 지원합니다. 시간 제한 시 유효한 기존 결과를 보존하고 증명된 범위만 표시합니다. 엔진이 없으면 설치 오류를 반환하며 다른 탐색으로 자동 전환하지 않습니다.
- 기본 점수: 오전 수업 × 10, 금요일 수업 × 16, 공강 20분당 1, 건물 변경 × 4, 등교일 × 12, 점심 1시간 미확보 일수 × 25, 30분 미만 연강 횟수 × 9, 하루 수업량 초과 과목 × 18. 켠 선호만 반영합니다. 관심 과목 포함 시 과목당 20을 차감합니다. 점심은 12–14시 안의 연속 60분을 기준으로 하며 하루 수업량은 선호 조건입니다.
- 위 점수는 **내 선호 함께 반영**에서 첫 목표로 사용합니다. 공강·등교일·수업량의 엄격한 기준을 선택하면 해당 프로필 순위만 적용합니다. 점심 선호와 필수 점심 조건은 구분됩니다. 정확한 목표 순서는 [CONTRACT.md](CONTRACT.md)에 있습니다.
- AI가 자유 문장을 검증 가능한 조건으로 해석한 뒤, 코드가 유효한 시간표를 생성합니다. AI는 그 안에서 3개를 골라 과목 선택 이유와 장단점을 설명합니다. 적용 조건을 화면에 표시하고, 알 수 없는 난이도·성적·과제량은 판단하지 않습니다.
- AI 결과의 후보 ID·중복·개수를 서버에서 검증합니다. 실패 시 오류를 표시하며 기존 결과에 AI 성공 표시를 붙이지 않습니다.
- AI는 데모의 추천 기능에만 사용합니다. 실제 개발의 AI 도입·인증 방식은 미정입니다.

## 실행 환경

- Windows, Google Chrome, Node.js 20.18.1 이상, Python 3.10 이상. AI 추천에만 Codex CLI 및 ChatGPT 로그인이 필요합니다.
- 기존 파서의 Cheerio·Playwright를 공유합니다. 실행 파일과 `npm start`는 누락된 구성 요소를 `../lms-parser`에 자동 준비합니다. 직접 서버를 실행하려면 먼저 `node prepare-lms.mjs`를 실행하세요.
- 최초 추천 엔진 설치: `npm run setup:solver`. `.venv`는 Git에 포함하지 않으며 Python 직접 지정은 `TIMETABLE_PYTHON` 환경 변수를 사용합니다.
- 일반 실행: `시간표 데모 시작.bat` / 개발용 직접 실행: `npm start` / 검증: `npm test`, `npm run test:ui`, `npm run test:solver`
- 로컬 주소: `http://127.0.0.1:4317`. 외부 네트워크에 공개하지 않습니다.
- 다른 포트: `PORT` 환경 변수. Codex 실행 경로: 필요할 때만 `CODEX_BIN` 지정.
- BAT는 `start.ps1`과 `windows-job.cs`로 서버 프로세스의 수명을 터미널에 묶습니다. 같은 포트가 이미 사용 중이면 중복 실행을 중단합니다.

## 검증

`npm test`는 추천 조건·선호 점수·후보 비교·일정 변경·ICS·저장 실패·Codex 연결 상태를 검증합니다. Chrome 브라우저에서는 320·390·768·1440px 화면과 과목 선택부터 저장, 반복 일정 수정·복원, 충돌 확인, 내보내기, 기록 복원, 빈 결과·오류·로딩 취소를 확인했습니다. 실제 계정 로그인과 유료 AI 요청은 이 UI 검증에서 실행하지 않았습니다.

OR-Tools 추가 테스트, 실제 세 경로의 solve 기록, 상태 경계 대역과 미실행 데이터 범위는 [solver/VALIDATION.md](solver/VALIDATION.md)에 구분해 기록합니다. 제공된 규칙 폴더에는 원본 CSV와 R001–R030·I031–I040 실행 스위트가 없으므로 676개 회귀 결과를 주장하지 않습니다.

## 연결 방식

LMS는 `../lms-parser/index.mjs`의 `LmsConnection`, `collectLms`, `calendarEvents`를 사용합니다. `lms-service.mjs`에서 `includeMaterials: false`로 호출하므로 일정 가져오기에서는 파일·영상·Commons 뷰어에 접근하지 않습니다. 개인용 다운로드 프로그램은 `LMS 모아 시작`으로 따로 실행합니다. 공통 모듈을 가져오는 것만으로 서버나 로그인 창이 실행되지 않습니다.

학교 로그인은 `%LOCALAPPDATA%\SSU Timetable LMS\login.dpapi`에 Windows 사용자별 DPAPI로 암호화해 보관합니다. 독립 도구의 보관함과 분리하며 서로 로그인 파일을 복사하지 않습니다. 이 프로젝트의 최초 연결은 학교 로그인이 필요하고, 이후 실행에는 자동 복원합니다. 학교의 재인증 요구 시 다시 연결해야 합니다. 학교 로그아웃은 프로젝트의 저장된 로그인만 지웁니다.

브라우저 화면을 닫아도 **데모 서버가 실행 중이면** 진행 중인 수집이 계속됩니다. 다시 열면 결과를 반영합니다. 터미널을 닫으면 수집과 연결이 종료됩니다. 예약 수집과 외부 캘린더 자동 동기화는 제공하지 않습니다. `npm run test:ui`는 실제 Chrome과 합성 LMS 데이터로 검증하며 실제 학교 계정에는 접근하지 않습니다.
