# 시간표 추천 데모

진로 추천은 [V2 설명 기반 추천](CAREER_V2.md)을 사용합니다. 이전 구현 기록은 [CAREER_V1.md](CAREER_V1.md)에 있습니다.

## 진로 기반 비교과 추천

홈의 **진로에 맞는 비교과 찾기**, 또는 **비교과 추천** 메뉴에서 희망 진로를 입력하면 공개 비교과 정보를 추천합니다. 과목 진로 검색 화면에서 입력한 진로를 이어 사용할 수도 있습니다.

- 수집된 모집 정보의 현재 한국 날짜를 확인하고 마감·미게재·기간 미확인 항목은 추천에서 제외합니다. 기본은 모집 중인 프로그램이며 **모집 예정도 포함**을 선택할 수 있습니다.
- 진로 검색어 확장 → 관련 후보 검색 → 최대 40개 AI 평가 순서로, 제목·운영부서·유형·공식 설명을 활용합니다. 새 임베딩/외부 검색 서비스는 사용하지 않습니다.
- 상세가 정상 확보되지 않았으면 설명을 만들어 넣거나 이전 설명을 현재 설명으로 사용하지 않고 제목·운영부서로 판단합니다. 결과에 근거 유형, 신청·활동 기간, 신청대상과 학교 원문·신청 진입 링크를 표시합니다.
- 36시간 이상 오래된 자료, 미래 시각 또는 전체 수집 미완료 자료는 새 추천에 사용하지 않습니다. 수집 데이터 버전이나 한국 날짜가 바뀌면 저장된 추천을 숨기고 재검색을 안내합니다. 활동기간은 매일 참석하거나 특정 시간에 진행된다는 의미가 아니므로 수업 시간 충돌을 추정하지 않습니다.
- 추천은 자동 신청·캘린더 추가·OR-Tools 필수 조건으로 연결되지 않습니다. 비교과 추천은 별도의 브라우저 저장 키를 사용하며 기존 시간표·캘린더·과목 추천 기록을 바꾸지 않습니다. AI에는 진로와 공개 프로그램 근거만 전달합니다.

### 수집 결과 연결

기본 파일은 `../extracurricular-collector/output/programs.json`입니다. 먼저 [수집기](../extracurricular-collector/README.md)를 실행한 뒤 이 앱을 시작하면 됩니다. 파일이 없거나 오래되면 화면에서 준비·갱신 필요 상태를 안내하며 가상 데이터로 대체하지 않습니다.

서버 배포에서는 환경변수로 실제 저장 위치를 지정합니다.

```bash
SSU_PROGRAMS_FILE=/var/lib/ssu-extracurricular/programs.json npm start
```

환경변수는 앱을 실행하는 서비스에 설정해야 합니다. 수집기와 웹 서비스가 서로 다른 사용자라면 파일 읽기 권한도 필요합니다. 수집 파일은 `0640`, systemd 저장 디렉터리는 `0750`이므로 웹 사용자를 `ssu-collector` 그룹에 추가하고 웹 서비스를 재시작하거나, 팀 환경에 맞는 공유 그룹/동일 서비스 사용자를 지정합니다. 운영 DB·인증 백엔드에 자동으로 연결한 기능은 아닙니다.

비교과 API는 `GET /api/programs/meta`, `POST /api/programs/recommend`입니다. 추천 요청 본문은 `{goal, includeUpcoming}`이며 기존 로컬 앱의 Origin·Host 보호와 Codex 연결을 사용합니다. AWS의 다중 사용자 API로 공개하려면 기존 인증·사용자별 모델 호출 구조에 별도로 연결해야 합니다.

검증은 모집 상태 재판정, 오래된 자료 차단, 제목 기반 판단, 모델 ID 위조·데이터 변경 거부, 기존 추천 보존과 브라우저 저장·모바일 흐름을 포함합니다. 실제 AI 계정의 추천 품질은 별도 확인이 필요합니다.

2026-11-26 로컬 검증: 전체 Node 자동 테스트 112개 통과(비교과 9개 포함), Chromium 브라우저 25개 통과·WebKit 선택 테스트 1개 건너뜀. 최종 비교과 API·브라우저 11개도 재확인했다. 실제 수집 4,072건에서 모집 중 31건·모집 예정 3건을 분리하고 AI 테스트 대역으로 후보 검색부터 응답 검증까지 확인했다. 수집기 Python 테스트 19개도 macOS·Ubuntu에서 통과했다. AWS 배포·실계정 AI 호출은 하지 않았다.

처음 한 번 `npm run setup:solver`로 OR-Tools를 설치한 뒤 상위 폴더의 **시간표 데모 시작.bat**를 더블클릭하면 터미널 하나에서 실행됩니다. 서버가 준비되면 **크롬 새 창**이 자동으로 열립니다. 기본 추천은 Codex 연결 없이 사용할 수 있습니다.

**종료: 터미널 창 닫기 또는 Ctrl+C.** 서버와 이 데모의 Codex 연결 프로세스가 함께 종료됩니다. 크롬 창은 자동으로 닫지 않습니다. 기존 VBS 파일도 같은 BAT를 실행합니다.

1. **내 시간표 만들기** → 학기·학과 선택 → 필수 과목 선택. **희망진로 검색**에서 같은 학기·학과로 저장한 추천 목록의 원하는 과목도 필수로 선택할 수 있습니다.
2. **생활 패턴 정하기** → 학점·요일·시간 설정 → **추천 시간표 보기**
3. 등교일·하루 수업량·공강 기준의 실제 후보 비교 → **이 시간표로 정하기** → 학기 저장

**더 세밀하게 설정하기**에서 하루 수업량, 점심·연강 선호, 총/전공/교양 학점 범위를 조정할 수 있습니다. **과목 고르기**에서 특정 과목을 필수 포함하거나 제외합니다. 관심 과목은 조건에 맞으면 우선 추천하고, 담은 관심 과목을 개별 해제할 수 있습니다.

세부 설정에는 엄격한 추천 기준과 **반드시 지킬 생활 조건**도 있습니다. 등교일 정확히/최대, 오전 수업 횟수/일수, 필수 연속 점심시간을 설정합니다. 불가능 판정 후 **허용할 변경 범위 고르기**로 선택한 항목만 최소 완화합니다. 수업 상세의 **이 분반 대신 다른 분반 찾기**는 같은 과목·총 학점을 유지하는 대체안을 찾습니다. 결과를 저장하기 전까지 원래 조건과 학기 일정은 바뀌지 않습니다.

AI 추천은 생활 패턴 화면의 **문장으로 요청하고 싶다면**에서 사용합니다. 이 화면에 진입하면 기존 Codex 로그인 상태를 확인하며, 연결이 필요한 경우 **Codex 연결**을 누릅니다. 요청 예: “수요일만 등교하고 전공 6학점, 교양 2학점으로 골라줘.” 로그인 취소는 기존 계정을 로그아웃하지 않습니다.

## 화면 구성과 구현

- [Figma 디자인](https://www.figma.com/design/8MiEDoEzXnAhiSUr9oiGdF?node-id=0-1)을 모바일 중심으로 구현했습니다. PC 주요 화면은 왼쪽 내비게이션과 시간표·비교 패널을 제공합니다.
- 차콜·블루와 과목별 세이지·라벤더·블루·피치·샌드 색상, 흰 카드와 미세한 그림자를 사용합니다. 그라데이션은 없습니다.
- 기존 HTML/CSS/JavaScript와 Node 서버를 유지하며, 추천 계산은 Python의 OR-Tools 9.15.6755를 사용합니다. LMS 연결은 공통 파서의 Cheerio·Playwright를 사용합니다. 아이콘은 Figma의 SVG, 글꼴은 로컬 Noto Sans KR 400·500·700입니다. 글꼴 라이선스는 `public/assets/OFL-NotoSansKR.txt`에 있습니다.
- `public/app.js`: 단계별 화면·탐색·API 연결. `public/ui.js`: 공통 UI·시간표·비교안 선택. `public/style.css`: 모바일·PC 스타일. `public/planner.js`: 기존 저장 형식을 유지하는 브라우저 저장소.
- 추천 실패·빈 결과·진행 중 화면, 키보드 모달 닫기, 화면 읽기용 레이블, 동작 줄이기 설정을 지원합니다.
- 화면 진입·추천안 전환·탭 이동·과목 선택·모달·알림에 짧은 애니메이션을 적용했습니다. 기기의 동작 줄이기 설정을 따르면 모션을 끄며, 과목 선택 시 키보드 포커스와 스크롤 위치를 유지합니다. 모바일의 내용 영역과 하단 버튼을 분리해 버튼이 내용을 가리지 않도록 했습니다.

## 데모 범위

- **희망진로 검색:** 진로 입력 → 과목명 기반 AI 평가 → 전공·교양 추천 목록 저장 → 이번 학기에 들을 과목만 필수 선택. 추천 목록은 새로고침 후에도 유지하며, 기수강 자동 제외는 적용하지 않습니다. 공식 선수과목이나 수강 자격을 판정하지 않으며 외부 검색·RAG는 미구현입니다.
- **학기 캘린더:** 추천 시간표의 학기 시작·종료일을 입력해 최대 31주까지 수업을 생성합니다. 초기 날짜는 예시이며 학교 학사일정을 직접 확인해야 합니다. 휴일·휴강은 자동 반영하지 않습니다.
- **내 LMS 일정:** 학교 연결 → 과목 선택 → 일정 가져오기. 시간표 없이도 개인 과제·시험·강의 마감과 학교 캘린더 일정을 표시합니다. 마감은 한국 시간의 한 시점으로 표시하고 수업 충돌에서 제외하며, 종일·여러 날 일정을 지원합니다. LMS 일정은 원문을 여는 방식으로 확인하고 학교의 변경 사항은 다시 가져와 반영합니다.
- 수업 클릭 시 **이번 일정만 / 같은 요일 수업의 이후 일정도**를 구분해 변경합니다. 휴강·취소 표시와 복원, 날짜·시간·장소 변경, 시험·보강·개인 일정 등록 및 시간 충돌 표시를 지원합니다. 기존 수업의 종류를 시험으로 바꾸면 대체 시험, 별도 일정 추가는 추가 시험입니다.
- **수강 경험:** 가상 조합 3개에서 관심 과목을 적용하고, 저장한 시간표(없으면 현재 추천안)와 함께 선택 이유를 기록합니다. 실제 선배 후기나 공개 게시판은 제공하지 않습니다.
- **ICS 다운로드:** 활성 일정을 한국 시간 기준으로 UTC 변환해 내보냅니다. 휴강·취소는 제외합니다. 파일 생성·시간 변환·한글 줄바꿈을 검증했으며 외부 캘린더 자동 동기화는 구현하지 않았습니다. 변경 후 다시 내보내야 하며 반복 가져오기는 중복 일정을 만들 수 있습니다.
- 학기 일정·내 기록은 `localStorage`에 저장합니다. 새 시간표는 지정한 적용일 이후의 수업에 반영합니다. 개인 일정·과거 일정은 보존하고, 분반 변경의 영향을 받는 시험·보강·개별 예외는 처리 방법을 확인한 후 저장합니다. [학기 캘린더 처리 계약](../docs/calendar-logic-handoff.md)에 호출 예제와 마이그레이션 방식이 있습니다.
- LMS 일정은 인증된 학교 사용자에서 만든 식별자로 별도 보관합니다. 다른 학교 계정으로 바꾸면 이전 계정의 일정은 보이지 않습니다. 같은 계정의 같은 일정은 갱신하고, 선택하지 않은 과목과 기존 수업·개인 일정은 유지합니다. 선택 과목의 정상 조회에서 사라진 일정만 제거하며, 부분 실패가 있으면 누락된 기존 일정을 보존합니다. 새 추천 시간표로 학기를 만들어도 LMS 기록은 유지합니다.

- `data/courses.json`·`data/courses.csv`의 2026년 1학기 2,462개·2학기 2,260개, 총 4,722개 분반을 사용합니다. 두 파일의 모든 행과 필드를 대조하는 테스트가 있습니다. 학기·학과 선택은 새로고침 후 복원됩니다.
- 59개 학과의 전공 조회경로를 반영하고 교양 전체를 함께 제공합니다. 이수구분이 `전`으로 시작하면 전공으로 분류하며, 교양 영역은 표시 정보로 보존합니다. 실제 자료에는 예시 카탈로그의 교과목군 중복 금지 규칙을 적용하지 않습니다.
- 학기와 과목번호 앞 8자리·이름·학점·분류가 같은 분반을 묶어 2,383개 과목 그룹으로 표시합니다. 시간 미등록 108개 분반은 안내 후 조합에서 제외하고, 과목의 필수 포함 조건은 임의로 제거하지 않습니다. 0.5학점·주말·복수 요일·요일별 강의실·공동강의 중복 시간을 처리합니다.
- 수강대상·수강유의사항은 분반 상세에 표시합니다. 학년·선수과목·수강 자격·기이수 내역·졸업 요건을 자동 판정하지 않으며 원본 여석은 실시간 수강 가능 여부로 사용하지 않습니다.
- 학기·학과를 바꾸면 과목·분반 선택과 추천 결과를 초기화합니다. 저장한 일정·수강 기록·진로 목록은 유지하며, 진로 목록은 학기·학과·자료 버전이 같을 때 사용합니다. 현재 저장소는 한 학기 캘린더를 관리하며 다른 학기의 추천안으로 기존 학기를 덮어쓰지 않습니다.
- 선택 과목당 한 분반, 모든 수업 시간 충돌, 가능한 요일·시작/종료 시간, 학점 범위, 필수 포함·제외를 검사합니다. 인접 수업의 종료와 시작이 같으면 시간상 함께 배치할 수 있습니다.
- 실제 CP-SAT 모델로 추천·대체·완화를 계산합니다. 엄격한 사전식 순위, 분반 집합 단위 중복 제거, 학점별 독립 대표안과 제한된 전수 열거를 지원합니다. 시간 제한 시 유효한 기존 결과를 보존하고 증명된 범위만 표시합니다. 엔진이 없으면 설치 오류를 반환하며 다른 탐색으로 자동 전환하지 않습니다.
- 기본 점수: 오전 수업 × 10, 금요일 수업 × 16, 공강 20분당 1, 건물 변경 × 4, 등교일 × 12, 점심 1시간 미확보 일수 × 25, 30분 미만 연강 횟수 × 9, 하루 수업량 초과 과목 × 18. 켠 선호만 반영합니다. 관심 과목 포함 시 과목당 20을 차감합니다. 점심은 12–14시 안의 연속 60분을 기준으로 하며 하루 수업량은 선호 조건입니다.
- 위 점수는 **내 선호 함께 반영**에서 첫 목표로 사용합니다. 공강·등교일·수업량의 엄격한 기준을 선택하면 해당 프로필 순위만 적용합니다. 점심 선호와 필수 점심 조건은 구분됩니다. 정확한 목표 순서는 [CONTRACT.md](CONTRACT.md)에 있습니다.
- AI가 자유 문장을 검증 가능한 조건으로 해석한 뒤, 코드가 유효한 시간표를 생성합니다. AI는 그 안에서 3개를 골라 과목 선택 이유와 장단점을 설명합니다. 적용 조건을 화면에 표시하고, 알 수 없는 난이도·성적·과제량은 판단하지 않습니다.
- AI 결과의 후보 ID·중복·개수를 서버에서 검증합니다. 실패 시 오류를 표시하며 기존 결과에 AI 성공 표시를 붙이지 않습니다.
- AI는 데모의 추천 기능에만 사용합니다. 실제 개발의 AI 도입·인증 방식은 미정입니다.

## 학기 캘린더 사용법

1. **학기 일정**을 열면 월요일부터 일요일까지의 주간 시간 격자가 기본으로 표시됩니다. 화면이 좁으면 **내 시간표**와 학기 캘린더의 주간 격자 안을 좌우로 밀어 다른 요일을 볼 수 있습니다. 주간 캘린더는 08:00–19:00을 기본 범위로 사용하고 이른 수업이나 늦은 일정이 있는 주에는 시간 범위를 넓힙니다.
2. **월간**과 **일간 목록**으로 전환해도 선택 날짜를 유지합니다. **이전**, **다음**, **오늘**, 날짜 입력으로 이동합니다. 월간의 날짜나 **더보기**를 누르면 그날의 전체 일정이 일간 목록에 표시됩니다. **월간에 일반 수업 표시**를 끄면 휴강·시험·보강·개인·LMS 일정이 남습니다.
3. 일정을 누르면 캘린더 위에 상세·편집 팝업이 열립니다. 기존 수업의 종류를 **이 수업을 대체하는 시험**으로 선택해 저장하면 시험이 표시됩니다. 휴강은 흐린 색과 취소선으로 표시하고, **일정 복원**은 취소 전에 수정한 날짜·시간·장소를 유지합니다. LMS 일정 팝업에서는 원문을 열 수 있습니다.
4. **일정 추가**는 선택한 날짜를 사용합니다. 주간의 빈 시간 칸을 누르면 그 칸의 시간이 채워집니다. 겹침 경고를 닫으면 입력 초안으로 돌아오고, **겹침을 확인하고 저장**을 누르면 변경을 적용합니다.

과목 색상은 보기 간에 같고, 시험과 보강은 종류 배지로 구분합니다. 모바일에서는 블록에 일정명을 우선 표시하며 일간 목록이나 상세 팝업에서 시간과 장소를 확인할 수 있습니다.

모바일·태블릿은 상단과 하단 메뉴 사이의 본문만 세로로 스크롤됩니다. 모바일 편집 시에는 하단 시트의 입력 부분을 스크롤할 수 있고 닫기와 저장 버튼은 별도 영역에 있습니다. 좁은 창에서는 내 시간표와 다음 일정이 위아래로 배치되고, 넓은 PC 창에서는 나란히 표시됩니다.

## 과목 고르기와 생활 패턴

- **과목 고르기**에서 전체·전공·교양 탭, 검색어, 이수구분, 학점, 대상 학년을 함께 사용할 수 있습니다. 같은 항목의 여러 선택은 하나만 맞아도 되고, 이수구분과 대상 학년은 같은 분반에서 일치해야 합니다. 학점과 학년 선택지는 현재 학기·학과의 자료를 사용합니다. **전체학년**은 자료에 명시된 대상 표시입니다. **필터 초기화**를 눌러도 담아 둔 과목과 학점은 유지됩니다.
- **생활 패턴 정하기**의 목표 학점은 담은 과목의 학점을 한 번씩 더해 설정합니다. 과목을 담지 않았다면 총 13·전공 9·교양 4가 기본입니다. 수동 목표를 입력하면 추가 학점은 선택한 전공·교양 학점을 포함하는 범위에서 추천됩니다. 직접 설정한 세부 범위에 선택 과목이 들어가지 않거나 선택한 과목이 24학점을 넘으면 수정할 조건을 알려줍니다.
- 등교 요일·수업 가능 시간 바로 아래 **선택 과목 수업시간**에서 맞는 분반 수, 안 맞는 이유, 분반별 강의실과 시간 블록을 확인할 수 있습니다. 같은 분반의 모든 블록이 현재 요일·시간에 맞아야 집계됩니다. 맞는 분반끼리의 시간 겹침은 별도로 표시합니다. `GET /api/meta`는 목록용 필터 정보만 추가하며, 선택된 과목의 분반 상세는 `POST /api/course-compatibility`로 받아 요일·시간이 바뀔 때 브라우저에서 재사용합니다.

2026년 2학기 AI소프트웨어학부에서 **전공 → 이수구분 선택 → 3학점 → 4학년**으로 `소프트웨어특강2`를 찾을 수 있습니다. 생활 패턴에서 수요일을 켜고 시작 가능 시각을 10:00에서 09:00으로 바꾸면 종료 가능 시각이 11:45 이후일 때 맞는 분반 수가 0개에서 1개로 바뀝니다.

## 과목 선택과 후보 비교에서의 경고

- **과목 고르기**에선 현재 학기·학과의 필수 과목과 고정 분반으로 가능한 수업 시간 조합을 확인합니다. 문제가 있으면 그 자리에서 필수 과목을 해제할 수 있습니다. 시간 미등록과 탐색 시간 초과는 확인 안내로 표시합니다. `POST /api/course-compatibility`는 필수 과목과 고정 분반이 포함된 과목의 시간만 사용합니다. 학점과 생활 패턴은 추천을 실행할 때 적용합니다.
- **추천 시간표**에선 현재 후보의 같은 요일에 연달아 배치된 수업 중 간격이 30분 미만인 구간을 살핍니다. **수업 사이 이동 안내**는 후보를 비교할 때 참고할 수 있으며 경고가 있는 후보도 저장할 수 있습니다.
- 실측한 동선은 [이동 데이터](public/campus-walking-routes.mjs)에 출발·도착 건물(`from`, `to`), 보행 분(`walkMinutes`), 출처(`source`), 측정일(`measuredOn`, YYYY-MM-DD)을 방향별로 기록합니다. 건물 간 이동에는 각 강의실 번호의 왼쪽 세 번째 숫자로 확인한 층 보정이 추가됩니다. 3층 이하는 1분, 4층 이상은 2분입니다. 같은 건물 안의 실측값에는 층 보정을 추가하지 않습니다. 층을 확인할 수 없는 건물 간 이동에는 수치 경고를 표시하지 않습니다.
- 배포본에 공개 보행로 추정값 445개 방향이 포함되어 있어 실행하면 바로 확인할 수 있습니다. 후보에 **공개 보행로 추정**과 출처가 표시됩니다. 우선순위는 현장 실측 → 네이버 확인 → 경험 안내 → 공개 보행로 추정입니다. 우회·접근점 확인이 필요한 106개 방향은 추정 경고에서 제외합니다. 네이버 확인값은 24개 건물의 방향별 기록 도구에서 갱신할 수 있습니다. [도보 기록과 후보 재현 안내](tools/campus-walk/README.md) · [OpenStreetMap 출처](https://www.openstreetmap.org/copyright)
- 문화관에서 정보과학관으로 향하는 구간은 사용자 경험에 따라 간격이 15분 이하이면 안내합니다. 보행시간과 측정일은 실측 후 입력하며, 실측값이 들어오면 남는 시간으로 경고를 판단합니다.

2026년 2학기 AI소프트웨어학부 기준으로 `소프트웨어특강2`와 `확률및통계`를 선택하면 수요일 10:30~11:45 충돌을 확인할 수 있습니다. `확률및통계`를 해제하고 `온디바이스AI`를 함께 선택하면 가능한 분반 조합이 있습니다.

이동 안내 두 사례 모두 2026-2 · AI소프트웨어학부에서 아래 두 과목만 담고 목표 6학점, 수업 가능 시간 10:00~18:00으로 설정합니다.

- **디지털포렌식개론 + 알고리즘**을 담고 화·목·금과 **등교일이 적은 순**을 선택합니다. **추천 시간표 보기**를 누르면 1번 후보에서 금요일 14:45 → 15:00 문화관 → 정보과학관 경험 안내를 확인할 수 있습니다.
- **데이터베이스응용 + 운영체제**를 담고 월·화·수·목과 **내 선호 함께 반영**을 사용합니다. 1번 후보는 화요일, 2번은 목요일 14:45 → 15:00 정보과학관 → 벤처중소기업센터 이동이 표시됩니다. 쉬는 시간 15분, 층 이동 포함 약 14분, 여유 1분입니다. 3번 후보로 바꾸면 안내가 사라집니다.

## 실행 환경

- Windows, Google Chrome, Node.js 20.18.1 이상, Python 3.10 이상. AI 추천에만 Codex CLI 및 ChatGPT 로그인이 필요합니다.
- 실행 파일과 `npm start`는 `prepare-dependencies.mjs`로 FullCalendar와 LMS 의존성을 각 폴더의 잠금 파일에 따라 설치합니다. 직접 서버를 실행할 때는 `timetable-demo`에서 `node prepare-dependencies.mjs`를 실행한 뒤 `node server.mjs`를 실행합니다.
- 캘린더는 **FullCalendar Standard 7.1.4**의 로컬 Vanilla JS 번들을 사용합니다. Node 서버가 필요한 스크립트·스타일·한국어 로캘을 같은 출처에서 제공합니다. [공식 설치 문서](https://fullcalendar.io/docs/vanilla-js) · [MIT 라이선스 고지](../docs/licenses/fullcalendar.txt)
- 최초 추천 엔진 설치: `npm run setup:solver`. `.venv`는 Git에 포함하지 않으며 Python 직접 지정은 `TIMETABLE_PYTHON` 환경 변수를 사용합니다.
- 일반 실행: `시간표 데모 시작.bat` / 개발용 직접 실행: `npm start` / 검증: `npm test`, `npm run test:ui`, `npm run test:solver`
- 로컬 주소: `http://127.0.0.1:4317`. 외부 네트워크에 공개하지 않습니다.
- 다른 포트: `PORT` 환경 변수. Codex 실행 경로: 필요할 때만 `CODEX_BIN` 지정.
- BAT는 `start.ps1`과 `windows-job.cs`로 서버 프로세스의 수명을 터미널에 묶습니다. 같은 포트가 이미 사용 중이면 중복 실행을 중단합니다.

## 검증

`npm test`는 추천 조건·선호 점수·후보 비교·일정 변경·ICS·저장 실패·Codex 연결 상태를 검증합니다. Chrome 브라우저에서는 320·390·768·1440px 화면과 과목 선택부터 저장, 반복 일정 수정·복원, 충돌 확인, 내보내기, 기록 복원, 빈 결과·오류·로딩 취소를 확인했습니다. 실제 계정 로그인과 유료 AI 요청은 이 UI 검증에서 실행하지 않았습니다.

`npm run test:ui`는 캘린더의 실제 수업 종류 선택과 저장, 필드별 편집, 휴강과 복원, 충돌 취소와 확인, 보기 전환, v1 데이터 읽기와 v2 저장, 저장 실패 및 LMS의 날짜 경계를 Chrome에서 검증합니다. 캘린더 스크린샷은 `.ui-qa/`에 생성됩니다. 다른 위치가 필요하면 `TIMETABLE_SCREENSHOT_DIR`에 경로를 지정합니다.

반응형 Chrome 테스트는 320·360·390·430·768·1024·1440px, 짧은 가로 화면, 터치 스와이프와 일정 저장을 확인합니다. 반응형 스크린샷의 출력 위치는 `TIMETABLE_RESPONSIVE_SCREENSHOT_DIR`로 바꿀 수 있습니다. 모바일 WebKit도 실행하려면 저장소 루트에서 다음 명령을 사용합니다.

```powershell
cd timetable-demo
node prepare-dependencies.mjs
node ../lms-parser/node_modules/playwright/cli.js install webkit
$env:TIMETABLE_TEST_WEBKIT = '1'
npm run test:ui
```

자동화된 뷰포트 변경은 실제 기기의 주소창, 노치, 화면 키보드 동작을 대체하지 않습니다.

OR-Tools 추가 테스트, 실제 세 경로의 solve 기록, 상태 경계 대역과 미실행 데이터 범위는 [solver/VALIDATION.md](solver/VALIDATION.md)에 구분해 기록합니다. 제공된 규칙 폴더에는 원본 CSV와 R001–R030·I031–I040 실행 스위트가 없으므로 676개 회귀 결과를 주장하지 않습니다.

## 연결 방식

LMS는 `../lms-parser/index.mjs`의 `LmsConnection`, `collectLms`, `calendarEvents`를 사용합니다. `lms-service.mjs`에서 `includeMaterials: false`로 호출하므로 일정 가져오기에서는 파일·영상·Commons 뷰어에 접근하지 않습니다. 개인용 다운로드 프로그램은 `LMS 모아 시작`으로 따로 실행합니다. 공통 모듈을 가져오는 것만으로 서버나 로그인 창이 실행되지 않습니다.

학교 로그인은 `%LOCALAPPDATA%\SSU Timetable LMS\login.dpapi`에 Windows 사용자별 DPAPI로 암호화해 보관합니다. 독립 도구의 보관함과 분리하며 서로 로그인 파일을 복사하지 않습니다. 이 프로젝트의 최초 연결은 학교 로그인이 필요하고, 이후 실행에는 자동 복원합니다. 학교의 재인증 요구 시 다시 연결해야 합니다. 학교 로그아웃은 프로젝트의 저장된 로그인만 지웁니다.

브라우저 화면을 닫아도 **데모 서버가 실행 중이면** 진행 중인 수집이 계속됩니다. 다시 열면 결과를 반영합니다. 터미널을 닫으면 수집과 연결이 종료됩니다. 예약 수집과 외부 캘린더 자동 동기화는 제공하지 않습니다. `npm run test:ui`는 실제 Chrome과 합성 LMS 데이터로 검증하며 실제 학교 계정에는 접근하지 않습니다.

공식 [Codex app-server](https://learn.chatgpt.com/docs/app-server)의 `account/read`, `account/login/start`, `account/login/completed`를 사용합니다. 인증 URL을 기본 브라우저로 열고, Codex가 OAuth 승인 결과와 인증 정보 저장·갱신을 처리합니다. 앱은 토큰이나 인증 파일을 읽거나 복사하지 않습니다.

추천 요청은 임시 대화로 실행하며 셸·앱·MCP·하위 에이전트 기능을 끄고 읽기 전용으로 제한합니다. 인증 URL·토큰·계정 이메일을 앱 로그나 화면에 출력하지 않습니다. 이번 데모는 로컬 사용을 전제로 합니다.
